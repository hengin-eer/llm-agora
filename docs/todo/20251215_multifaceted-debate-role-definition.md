# 多面的な議論のためのロール定義と実装計画

**作成日**: 2025年12月15日
**目的**: 従来の「肯定 vs 否定」の二元論を超え、より多角的で深みのある議論を実現するためのロール定義とシステム設計を行う。

---

## 1. 背景と課題

現在のシステムは「肯定派」と「否定派」の対立軸を中心に設計されている。しかし、複雑な社会課題や抽象的なテーマにおいては、単なる賛否だけでは議論が深まらない場合がある。
「自律型AIの合議エージェント」を目指すにあたり、異なる視点や専門性を持つ複数のエージェントが相互作用する仕組みが必要である。

## 2. 新しいロールの定義（案）

ユーザーが自由にカスタマイズできることを前提としつつ、プリセットとして以下のロールを用意する。

### A. 基本ロール（既存）
- **肯定派 (Proponent)**: 議題に対して積極的な支持を行い、メリットを強調する。
- **否定派 (Opponent)**: 議題に対して批判的な立場を取り、リスクやデメリットを指摘する。
- **ファシリテーター (Facilitator)**: 議論の整理、論点の明確化を行う。

### B. 拡張ロール（新規）
- **批判的思考者 (Critical Thinker)**:
  - 役割: 前提条件を疑い、論理的な飛躍やバイアスを指摘する。
  - プロンプト方針: 「なぜそう言えるのか？」「隠れた前提は何か？」を問い続ける。

- **データ・事実重視 (Fact Checker / Data Analyst)**:
  - 役割: 客観的な証拠や具体例を要求し、議論を現実に引き戻す。
  - プロンプト方針: 「具体的な数値や事例はあるか？」「それは一般化できるか？」を確認する。

- **創造的思考者 (Creative / Out-of-the-box Thinker)**:
  - 役割: 既存の枠組みにとらわれない代替案や新しい視点を提示する。
  - プロンプト方針: 「もし全く別の方法があるとしたら？」「逆の視点から見ると？」を提案する。

- **調停者 (Mediator / Synthesizer)**:
  - 役割: 対立する意見の共通点を見出し、建設的な妥協点や統合案を探る。
  - プロンプト方針: 「AとBの意見の共通項は何か？」「両立させる方法はないか？」を模索する。

- **専門家 (Domain Expert)**:
  - 役割: 特定の分野（経済、倫理、技術など）に特化した視点を提供する。
  - プロンプト方針: ユーザーが分野を指定可能にする（例：「経済学者の視点で...」）。

## 3. 実装計画

### フェーズ1: ロール定義のデータ構造化
- 現在のハードコードされた `DEBATE_ROLES` を、動的に生成・編集可能な配列/オブジェクトに変更する。
- 各ロールは以下のプロパティを持つ:
  - `id`: 一意のID
  - `name`: 表示名
  - `systemPrompt`: AIへの指示
  - `color`: UI表示用の色（オプション）
  - `icon`: アイコン（オプション）

### フェーズ2: ロールカスタマイズUIの実装
- **ロール管理画面**:
  - プリセットからロールを選択して追加
  - カスタムロールの作成（名前とプロンプトを編集）
  - ロールの順序並べ替え（議論の順番に影響）
  - ロールの削除

### フェーズ3: 多面的議論モード (Multifaceted Mode) の実装
- 従来の `Fixed` / `Loop` モードに加え、`Multifaceted` モードを追加（または既存モードを拡張）。
- **ロジック**:
  1. ユーザーが設定したロールリスト（例: 肯定→否定→批判→創造→調停）を順に実行する。
  2. 各エージェントは、直前の発言だけでなく、会話履歴全体（あるいは直近N件）を参照して発言する。
  3. 設定されたラウンド数だけリストを周回する。

### フェーズ4: UIへの反映
- チャット画面で、どのロールが発言しているかを明確に区別する（名前、色）。
- 現在の「肯定」「否定」の固定表示を廃止し、動的なロール名表示に対応する。

## 4. 今後のステップ

3. 議論実行ロジックを、動的ロールリストに基づいてループするように改修する。
